## این چیست؟

**سولارپس تونل** یک پل امن بین **سرور ایران** و **سرور خارج** می‌سازد تا سرویس‌هایت
— کانفیگ V2Ray/WireGuard، پنل، بازی، تماس تصویری — از داخل ایران سریع و پایدار در
دسترس باشند.

کاربران تو فقط به **سرور ایران** وصل می‌شوند؛ ترافیک از تونل عبور می‌کند و از سرور
خارج به اینترنت آزاد می‌رسد.

```
کاربر  ─────►  سرور ایران  ═════[ تونل رمزنگاری‌شده ]═════►  سرور خارج  ─────►  اینترنت
```

راه‌اندازی کامل با یک **منوی تعاملی** انجام می‌شود — بدون ویرایش دستی هیچ فایلی.

### چرا سولارپس؟

- ⚡ **کم‌تأخیر و پایدار** — مسیر داده‌ی جداگانه برای پکت‌های بلادرنگ
- 🛡️ **مقاوم در برابر فیلترینگ** — چندین transport، از جمله ترافیکِ شبیه‌نویز و ضدِ active-probe
- 🎮 **بهینه برای بازی** — حالت‌های KCP و datagram با کمترین پرش (jitter)
- 🔌 **چند سرویس با یک تونل** — چند پورت هم‌زمان روی یک اتصال
- 🔁 **خودترمیم** — قطعی موقت خودکار و بدون دخالت تو ترمیم می‌شود
- 🧩 **راه‌اندازی ساده** — منوی تعاملی، پروفایل آماده برای هر نوع مصرف
- 🔄 **آپدیت یک‌خطی** — تونل‌ها خودکار روی نسخه‌ی جدید بالا می‌آیند

## 🚀 نصب

روی **هر دو** سرور (ایران و خارج) این یک خط را اجرا کن:

```bash
curl -fsSL https://raw.githubusercontent.com/SolarPass-cloud/solarpass-tunnel/main/install.sh | sudo bash
```

نصب‌کننده آخرین باینری را از Releases می‌گیرد، در `/usr/local/bin/solarpass-tun`
می‌گذارد، بهینه‌سازی شبکه (BBR) را اعمال می‌کند و دستور آپدیت را می‌سازد.

سپس کافی است اجرا کنی:

```bash
solarpass-tun
```

## 🔑 راه‌اندازی گام‌به‌گام

ترتیب کار: **لایسنس ← ایران ← خارج**.

سمت ایران یک **کدِ base64** تولید می‌کند که همه‌چیز (توکن، transport، پورت‌ها) داخلش
است؛ همان را روی سرور خارج paste می‌کنی. لازم نیست هیچ مقداری را دستی یکی کنی.

| گام | کجا | کار |
|:---:|-----|-----|
| **۱** | [پنل کاربری](https://solarpass.org/dashboard/tunnel) | یک پلن انتخاب کن و **IP سرور ایران** را وارد کن → یک **license key** می‌گیری |
| **۲** | سرور **ایران** | `solarpass-tun` → گزینه‌ی **۱** → `IP:PORT` سرور خارج، transport و پورت‌ها را بده → یک **کد base64** می‌گیری، کپی‌اش کن |
| **۳** | سرور **خارج** | `solarpass-tun` → گزینه‌ی **۲** → کد base64 را paste کن، سپس **license key** را وارد کن |
| **۴** | — | هر دو سمت بالا می‌آیند. کاربرانت به پورت روی **سرور ایران** وصل می‌شوند |

> 💡 **لایسنس فقط روی سرور خارج وارد می‌شود.** سمت ایران لایسنس نمی‌خواهد.

## 🎛️ منوی اصلی

بعد از اجرای `solarpass-tun` این گزینه‌ها را می‌بینی:

| گزینه | کار |
|:---:|-----|
| **0** | نصب پیش‌نیازها و آماده‌سازی سرور |
| **1** | راه‌اندازی سمت ایران _(تولید base64)_ |
| **2** | راه‌اندازی سمت خارج _(paste کردن base64)_ |
| **3** | حالت **Auto-Config** _(مذاکره‌ی دوطرفه)_ |
| **4** | مدیریت تونل‌ها _(start / stop / restart / status)_ |
| **5** | مشاهده‌ی لاگ زنده‌ی تونل |
| **6** | وضعیت و آمار مصرف |
| **7** | ویرایش کانفیگ _(ویزارد یا JSON)_ |
| **8** | حذف نصب _(یک تونل یا همه)_ |
| **m** | متفرقه _(بلاک ICMP / ری‌استارت خودکار)_ |

## 🎯 پروفایل مصرف

هنگام ساخت تونل، **نوع مصرف** را می‌پرسد و همه‌ی پارامترهای داخلی (اندازه‌ی پنجره،
بافرها، فاصله‌ی keepalive) خودکار برای همان کار تنظیم می‌شوند. transport عوض نمی‌شود.

| پروفایل | مناسبِ |
|---------|--------|
| `gaming` | بازی آنلاین / WireGuard — کمترین ping |
| `lowlatency` | تماس صوتی‌تصویری / RDP / SSH — تعاملی |
| `highload` | دانلود سنگین / استریم — بیشترین سرعت |
| `bypass` | سخت‌گیرترین فیلترینگ (obfs + fragment) |
| `balanced` | مصرف عمومی _(پیش‌فرض)_ |

> اگر مطمئن نیستی، `balanced` را بگذار؛ بعداً از گزینه‌ی **۷** قابل تغییر است.

---

## 🧪 کدام transport را انتخاب کنم؟

| مقدار | مناسبِ | توضیح |
|-------|--------|-------|
| `tcp` | عمومی و پایدار | ساده و مقاوم — اگر شک داری با این شروع کن |
| `ws` / `wss` | عبور از CDN و رِوِرس‌پروکسی | ترافیک شبیه وب‌سوکت (`wss` رمزگذاری‌شده) |
| `tcpmux` / `wsmux` / `wssmux` | چند کاربر روی یک تونل | مالتی‌پلکس روی یک کانکشن |
| `quic` / `quicmux` | تأخیر پایین (UDP) | مبتنی بر QUIC |
| `hysteria` | لینک‌های پرافت‌وخیز | QUIC + congestion تهاجمی + obfs |
| `gamepass` | **گیم و تماس تصویری** | datagram روی WebSocket، بدون head-of-line |
| `ultimatepass` | **محیط‌های سخت‌گیر** | ترافیکِ کاملاً درهم‌ریخته + AEAD، مقاوم در برابر active-probe |
| `ultimategamepass` | **گیمِ کم‌تأخیر** | تونل KCP روی UDP — جبران سریع loss بدون دوبرابرشدن ping |
| `speedpassmux` | گیمِ چندکاربره | همان KCP با چند کاربر روی یک تونل |
| `spoof` | سخت‌ترین فایروال‌ها | IP-spoofing روی UDP خام (فقط Linux + root) |

**انتخاب سریع:**

- 🎮 بازی → `ultimategamepass` یا `gamepass`
- 🛡️ فیلترینگ شدید → `ultimatepass` یا `spoof`
- 📺 دانلود و استریم → `wssmux` یا `tcpmux`
- 🤷 مطمئن نیستی → `tcp`

> ⚠️ **transport های مبتنی بر UDP** (`quic`، `hysteria`، `ultimategamepass`، `spoof`)
> نیاز دارند UDP بین دو سرور باز باشد. از ۲۰۲۵ بعضی مسیرها UDP را جز پورت ۵۳
> می‌بندند؛ اگر تونل بالا نیامد یک transport مبتنی بر TCP
> (`tcp` یا `ultimatepass`) را امتحان کن.

## 🔀 حالت اتصال (Dial Mode)

هنگام راه‌اندازی می‌پرسد چه کسی به چه کسی وصل شود:

| حالت | یعنی | کِی به کار می‌آید |
|------|------|-------------------|
| `iran-to-kharej` | ایران به خارج وصل می‌شود | حالت پیش‌فرض و رایج |
| `kharej-to-iran` | خارج به ایران وصل می‌شود | وقتی خارج نمی‌تواند پورت باز کند یا پشت NAT است |
| `auto` | هر دو را امتحان می‌کند | وقتی مطمئن نیستی کدام مسیر باز است |

## 🔄 به‌روزرسانی

```bash
sudo solarpass-tun-update
```

آخرین نسخه را می‌گیرد و **تونل‌های در حال اجرا را خودکار روی نسخه‌ی جدید ری‌استارت
می‌کند**. نیازی به نصب دوباره یا تنظیم مجدد نیست.

> ⬆️ **اگر قبلاً نسخه‌ی SkyPass را داشتی:** دستور قدیمیِ `skypass-tun-update` دیگر
> کار نمی‌کند. یک‌بار همان دستور **نصب** بالا را اجرا کن؛ تونل‌ها، کانفیگ‌ها و
> سرویس‌های systemd **خودکار منتقل می‌شوند** و نصب قدیمی پاک می‌شود. لایسنس، پورت‌ها
> و transport دست‌نخورده می‌مانند.

---

## ⌨️ دستورهای خط فرمان

برای کارهای روزمره منو کافی است، ولی این دستورها هم در دسترس‌اند:

| دستور | کار |
|-------|-----|
| `solarpass-tun` | باز کردن منوی تعاملی _(پیش‌فرض)_ |
| `solarpass-tun --version` | نمایش نسخه‌ی نصب‌شده |
| `solarpass-tun restart-all` | ری‌استارت همه‌ی تونل‌های ذخیره‌شده |
| `solarpass-tun export -c <file>` | گرفتن خروجی base64 از یک کانفیگ JSON |
| `solarpass-tun run -c <file>` | اجرای مستقیم یک تونل از فایل JSON |
| `solarpass-tun run-b64 <کد>` | اجرای مستقیم یک تونل از رشته‌ی base64 |

> `run` و `run-b64` تونل را در **پیش‌زمینه** اجرا می‌کنند (برای تست و دیباگ).
> برای اجرای دائم از منو استفاده کن تا سرویس systemd ساخته شود.

## 📂 مسیرها و سرویس‌ها

| چی | کجا |
|----|-----|
| باینری | `/usr/local/bin/solarpass-tun` |
| کانفیگ‌ها | `/etc/solarpass/` |
| سرویس هر تونل | `solarpass-<نام تونل>.service` |

مشاهده‌ی لاگ با systemd:

```bash
journalctl -u solarpass-<نام تونل> -f
```

> گزینه‌ی **۵** منو همین کار را با نمای بهتر انجام می‌دهد.

## 📋 پیش‌نیازها

- **لینوکس** روی `amd64` یا `arm64` (اوبونتو یا دبیان توصیه می‌شود)
- دسترسی **root** (برای نصب و بهینه‌سازی شبکه)
- یک **license** فعال از [پنل کاربری](https://solarpass.org/dashboard/tunnel)
- پورت تونل بین دو سرور باز باشد (TCP یا UDP بسته به transport)

باینری **استاتیک** است (musl) و به هیچ کتابخانه‌ی سیستمی وابسته نیست — روی هر توزیعی اجرا می‌شود.

## 🩺 عیب‌یابی

<details>
<summary><b>تونل بالا نمی‌آید و می‌گوید license نامعتبر است</b></summary>

سه چیز را چک کن:

1. لایسنس منقضی نشده باشد.
2. لایسنس روی **سرور خارج** وارد شده باشد، نه ایران.
3. **IP سرور ایران** که در پنل ثبت کرده‌ای با IP واقعی سرور ایرانت یکی باشد.

اگر IP سرور ایرانت عوض شده، از [پنل](https://solarpass.org/dashboard/tunnel) به‌روزش کن.
</details>

<details>
<summary><b>تونل وصل می‌شود ولی سرعت پایین است</b></summary>

- پروفایل مصرف را متناسب کن (گزینه‌ی **۷**): برای دانلود `highload`، برای بازی `gaming`.
- اگر روی transport مبتنی بر UDP هستی، مطمئن شو مسیر UDP را محدود نکرده است.
- `wssmux` یا `tcpmux` را برای ترافیک سنگین امتحان کن.
</details>

<details>
<summary><b>تونل مدام قطع و وصل می‌شود</b></summary>

- ابتدا با `tcp` تست کن؛ اگر پایدار بود یعنی مسیرِ UDP مشکل دارد.
- از گزینه‌ی **۵** لاگ زنده را ببین تا علت دقیق قطعی مشخص شود.
- اگر خارج پشت NAT است، حالت `kharej-to-iran` یا `auto` را امتحان کن.
</details>

<details>
<summary><b>بعد از آپدیت باید دوباره تنظیم کنم؟</b></summary>

نه. `sudo solarpass-tun-update` باینری را عوض می‌کند و تونل‌های ذخیره‌شده را خودکار
روی نسخه‌ی جدید بالا می‌آورد.
</details>

<details>
<summary><b>می‌توانم چند سرویس را با یک تونل رد کنم؟</b></summary>

بله. در بخش پورت‌ها چند پورت اضافه کن؛ همه از یک تونل عبور می‌کنند. برای هر پورت
مشخص می‌کنی TCP باشد یا UDP یا هر دو.
</details>

<details>
<summary><b>چند تونل هم‌زمان روی یک سرور ممکن است؟</b></summary>

بله. هر تونل نام و سرویس systemd جدا دارد. کافی است هر بار از گزینه‌ی **۱** یا **۲**
یک تونل جدید با نام متفاوت بسازی.
</details>

<details>
<summary><b>قبلاً SkyPass داشتم؛ برای مهاجرت چه کار کنم؟</b></summary>

فقط یک‌بار دستور **نصب** بالا را اجرا کن. نسخه‌ی جدید خودش:

- تونل‌ها و کانفیگ‌ها را از `/etc/skypass` به `/etc/solarpass` منتقل می‌کند،
- سرویس‌های `skypass-*.service` را متوقف و با `solarpass-*.service` جایگزین می‌کند
  (تونل‌هایی که بالا بودند دوباره بالا می‌آیند)،
- باینری و دستور آپدیتِ قدیمی را پاک می‌کند.

لایسنس، پورت‌ها و transport همان‌طور که بودند می‌مانند.
</details>
